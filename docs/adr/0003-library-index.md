# 角色库轻量索引、立绘选择与收藏

状态为已采用，2026-11-14。

原库将全部图片 data URL、来源响应与角色资料写在 `library.json`，每次换图都会序列化全库、检查全部归档，并通过桌面桥接返回全库。写入量随图片体积增长。

当前磁盘格式使用 `format_version = 2`。`library.json` 保留设置、收藏夹、角色顺序，每个角色记录身份、完整版本的 SHA-256 摘要、`selected_art` 和 `favorite`。完整资料保存在角色专属目录的 `profile-<内容摘要>.json` 中，兼容旧摘要目录及新的罗马字命名，详见 [角色归档 ADR](0002-character-archive.md)。图片原始字节、透明图、超分结果与 API 快照保持完整。加载时校验摘要、身份和路径，缺失或损坏报错。旧 v2 索引缺少 `favorite` 时沿用角色档案中的收藏值；显式的 `false` 会覆盖档案中的 `true`。内存继续使用完整 `Library` 模型。

旧格式可以直接加载。首次成功写入先准备并刷盘完整归档，然后原子替换为轻量索引。迁移失败保留旧文件，已有历史归档保留。普通变更比较前后角色，仅变化的角色生成完整版本，设置和收藏夹变更复用原有版本引用。

立绘选择属于展示偏好，单独更新当前索引，不为每次点选生成包含全部图片的新历史版本。`select_artwork` 在后台线程中与其他写操作共用事务锁，原子提交成功后才更新后端内存，响应仅包含身份和选择序号。旧 `mutate_library/art` 入口复用同一存储操作。

收藏同样写入轻量索引。首页、角色库的 `mutate_library/favorite` 和批量收藏、取消收藏的 `batch_characters` 共用 `store::set_favorites`，先验证全部身份，再在库事务锁内原子写入，成功后才发布内存。已采用索引格式的库仅更新 `library.json`，不读取或生成角色档案，不复制全库。响应为 `FavoriteUpdate { ids, favorite }`，前端按请求 ID 接收后仅应用收藏字段；失败保留原状态及批量选择。通用命令的其他动作继续返回原有库结构。旧整库格式首次操作仍需准备归档以迁移为索引。

前端单独维护待保存的预览，点选立即显示已有图片。请求串行执行，同一角色连续点选合并为最后一次选择。确认响应只更新已保存序号，不覆盖较新的预览。失败显示错误并退回已确认的选择，之后已排队的用户选择继续提交。导航期间预览同样供首页、角色库和收藏夹使用。

永久删除沿用持久删除意图和可重试清理。恢复时先从索引排除已确认删除的身份，再读取剩余归档，避免因已删除的版本文件而阻断恢复。其余写操作在删除意图未完成时仍受阻止。

角色库排序使用 `settings.library_order = { sort, descending, custom_order }`，旧文件缺省为添加顺序、升序与空自定列表。`set_library_sort` / `reorder_characters` 共用库事务锁和原子索引替换，成功后才发布内存及轻量 `Order` 响应，不序列化图片或生成新的角色版本。初次写入旧整库格式仍先准备归档。排序保持 `characters` 数组的添加顺序，删除清理自定列表中的身份；新增角色按规范化姓名及 ID 追加，不打乱已有自定位置。

该变更减少换图、设置和收藏夹操作的磁盘写入。首次加载仍需读取完整资料，资料变更仍会保存该角色的完整版本；图片独立去重存储属于进一步的数据格式优化。

本次检查还确认以下入口存在额外的大数据处理，作为后续优化位置。

- 语言、字号、搜索源、标签源、AI 默认提供方和代理设置，以及收藏夹增删改、成员增删，仍通过通用事务复制、比较并回传全库，磁盘可复用未变角色的档案引用。
- 标签显示的添加、改名、隐藏、排序和重置会保存该角色的完整档案，并回传全库。
- 自动标签补全的命令返回全库，前端只使用成功信号，随后又通过 `load_library` 重读最新库以防并发状态回退。
- AI／数据源连接操作只需设置，但 `connections::connection_action` 内仍通过 `commands::read` 复制全库。主题、配色和正常立绘选择入口已采用轻量响应。
- 删除角色时，`store::deletion::commit` 调用无前序库参数的 `prepare`，会重新序列化、计算摘要并检查保留角色的档案；若其收藏或选图已偏离档案快照，还会为保留角色生成新版本。
