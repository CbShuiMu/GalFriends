# 软件目录内的角色资料归档

状态：已采用，2026-11-14。

按用户要求，当前库改为可执行文件旁 `characters/library.json`。旧 Tauri 数据目录的 GalFriends 库仅在新库不存在时读取；首次加载命令在后台完成复制与归档，旧文件不删除、不覆盖。新库损坏时直接报告错误，不能退回旧库掩盖损坏。凭据继续使用原 GalFriends 配置路径作为命名依据，避免迁移资料后丢失登录状态。

每个角色在 `<罗马字>--<身份 SHA-256>/` 下追加 `profile-<JSON 内容 SHA-256>.json`，语音素材与模型放在同目录的 `voice/`。罗马字优先来自已标明的来源字段，其次使用本身为拉丁字母的主名。目录名规范化 Windows 文件名字符，完整身份摘要区分同名角色。缺少对应姓名时使用 `character-<身份摘要>/`。已有罗马字目录按摘要定位，后续姓名变动保持路径稳定。

升级启动时将只有档案及内置配置、表情素材的旧摘要目录整体重命名，旧索引与历史版本仍按摘要读取。包含自定义文件或旧语音素材的目录保留原路径，避免影响已有绝对路径引用。拒绝归档路径中的符号链接与 Windows 重解析点。完整角色记录包含 API 响应快照、所有分类别名、来源关系、图片索引、超分数据和本地显示调整。已有内容必须匹配摘要。

普通保存先刷盘归档版本，随后使用既有原子替换提交当前库，成功后才发布内存状态。归档或当前库保存失败时旧库保持有效；可能留下尚未成为当前库的完整历史版本，但不会发布失败结果。

按后续用户要求，删除角色改为永久清除当前记录、收藏关联和整个角色专属目录，包含全部版本、API 快照、图片与超分数据。单个与批量删除均通过 `store::save_changes` 识别删除集合；收藏夹删除只清理关系，标签隐藏仍保留来源数据。

多文件删除无法与 JSON 替换组成文件系统原子事务，因此使用可续做的删除意图：先序列化并刷盘新库临时文件、准备保留角色的归档、验证全部目标目录边界与链接，再刷盘 `.pending-character-deletion.json` 中的角色 ID 集合。之后删除目标目录、原子替换库，最后清除意图文件。只有全部成功后发布内存；失败保留确认窗口并报错。意图存在时阻止其他写入，同一删除可重试；刷新或重启加载根据已确认的 ID 继续清理，再读取新库。清理中断可能已删除部分历史文件，不回滚不可逆删除，不能让旧记录在重启后重新生成归档。若库缺失或损坏则报错，不回退样本或旧迁移副本。

删除边界只限当前 `characters/` 目录，按身份摘要定位专属目录。首次迁移留下的旧 GalFriends 副本仍作为独立备份保留，外部原图、源游戏、存档及打包共享样本资源留在原处。批量目标全部通过路径检查后才开始清理；文件占用等中途错误由持久意图支持重试。

原图仍保留 Bangumi URL，既有超分 PNG data URL 随资料一起归档；这不是全部远程原图的离线镜像。软件目录不可写时报告错误，不静默回退。没有新增第三方依赖。
